Looking at this PRD for VouchCare, here's my honest assessment:

What's strong

The problem statement is genuinely excellent. The quantitative data (92.9% self-referral rate, 84.1% provider deficit post-HMO cycles, ~44.6% patient satisfaction) makes the pain feel real and defensible. The user personas — Funke, Dr. Ibrahim, Chidi, Mrs. Adeyemi, Musa — are specific enough to be useful, not just decorative. The low-bandwidth consideration for Musa in Kaduna shows the team is thinking about real Nigerian infrastructure constraints, which is a sign of maturity.

The value proposition is also sharp: merging clinical triage with instant payment rails is a genuinely differentiated angle, not just another symptom checker.

Where it needs work

The biggest gap is the Key Features and Releases section — it's literally a template placeholder. For a product targeting a March 25th release (12 days away as of this document), there are no actual defined features, no release phases populated, and no mapped user stories beyond a copy-pasted template with TikTok-style examples still in there ("Browse videos", "Create and edit video"). That section needs to be completely replaced.

The User Stories section is the same issue — it's a video app template that was never cleaned up. That's a credibility problem if this goes to stakeholders or engineering.

The competitor analysis section is empty. Given that you're positioning against diagnostic AI tools and HMO portals, even a brief table would strengthen the case.

The technical architecture is completely absent. For a product this complex — real-time payment orchestration, AI triage, split-payment rails, low-bandwidth optimization — engineering and design need at least a high-level system design, API dependencies (is Interswitch being used?), and data flow for the HMO ↔ Hospital ↔ Patient triangle.

The success criteria are good but some metrics lack baselines. "Raise NPS from 44% to 80%" is great. But "reduce man-hours by 50%" needs a current baseline to be meaningful to engineering or finance.

Summary verdict

The discovery and framing work (problem, personas, value prop) is genuinely solid — probably an 8/10. But the execution sections (features, user stories, technical requirements) are 2/10 — mostly unpopulated templates. If this is going to engineering on March 25th, those sections need urgent attention in the next few days.

What are the technical requirements to achieve this on the backend side of this
Mar 16

This is a well-thought-out product. Let me break down the backend technical requirements by domain, mapped to what the PRD is actually asking for.
1. Core Architecture

The PRD describes three distinct portals (Patient mobile, Hospital desktop, HMO desktop) with real-time state shared across all three. That points to:

Recommended stack approach:

    API layer: REST + WebSocket (WSS) — REST for CRUD operations, WebSockets for real-time claims dashboard
    Event-driven backbone: A message broker (Redis Pub/Sub or a lightweight queue like BullMQ) to propagate state changes (e.g., token scanned → claim triggered → payment settled) across portals in real-time
    Database: PostgreSQL as the primary relational store (HMO policies, claims, users, hospitals) + Redis for caching policy matrices and session tokens

2. Authentication & Identity

The PRD specifies Phone + OTP login and RBAC across portal types.

Requirements:

    OTP delivery via SMS (Termii or Twilio for Nigerian numbers)
    Short-lived JWT access tokens + refresh token rotation
    RBAC roles: patient, receptionist, accountant, medical_director, claims_officer, network_manager, hmo_admin
    Each role scopes what data they can read/write — critical because hospital accountants should never see patient triage data

3. AI Triage Engine

The PRD says the triage runs a "local decision-tree algorithm" cross-referenced against a cached HMO Policy Matrix.

Requirements:

    A symptom intake API endpoint that accepts free-text or structured symptom input
    ICD-10 code mapping — you'll need either a static ICD-10 dataset loaded into PostgreSQL or a third-party clinical NLP API (like Infermedica or a fine-tuned Claude/GPT call)
    HMO Policy Matrix stored in Redis as a structured JSON cache, keyed by hmo_id + plan_id, describing covered ICD-10 ranges and tier authorizations
    Triage result returns: recommended care tier (Primary/Secondary/Tertiary), nearest authorized facilities, estimated co-pay, and a session ID that seeds the Referral Token
    For the hackathon/MVP: a rules-based decision tree is fine — you can back it with an LLM call for symptom parsing but keep the policy cross-reference deterministic

4. Referral Token (QR Digital Handshake)

The PRD specifies AES-256 encrypted, time-sensitive, PKI-validated tokens that refresh every 60 seconds.

Requirements:

    Token payload: { patientId, sessionId, triageResult, hmoAuthStatus, facilityId, expiresAt }
    Encrypt payload with AES-256-GCM, sign with a private key (RS256 JWT or similar)
    Store token metadata in Redis with a 60-second TTL — not the full payload, just the hash for validation
    Scan endpoint: hospital sends scanned token → backend decrypts, validates signature, checks TTL, returns authorization status
    "Payment Guaranteed" flag is set only after HMO policy validation passes during triage

5. Real-Time Claims Dashboard

The PRD specifies WebSocket-based live updates for hospital accountants.

Requirements:

    WebSocket server (Socket.io or native ws on Node.js, or use Go's gorilla/websocket if you go that route)
    Rooms scoped per hospital_id — when a patient token is scanned, emit a claim:new event to that hospital's room
    Events to handle: claim:new, claim:authorized, claim:settled, claim:flagged
    Read-only mobile view for front desk means the same WebSocket feed but a filtered event subset based on RBAC role

6. Payment Rails (Interswitch Integration)

This is the most complex backend domain. The PRD references Interswitch Transfer APIs, Webpay, and Paycode.

Requirements:

    Escrow model: When a triage session is confirmed, initiate a pre-authorization hold against the HMO's registered Interswitch wallet — this is what enables the "Payment Guaranteed" status on the token
    Co-pay split: On claim adjudication, calculate totalBill - hmoAllowableAmount = patientCopay, then trigger two separate Interswitch transfers: one from HMO escrow to hospital wallet, one charging patient via Webpay/Paycode
    Paycode (Feature I): Call Interswitch Paycode API to generate a cardless withdrawal code tied to the co-pay amount — hospital "pulls" it at the billing desk
    Settlement reconciliation: Store claimId ↔ interswitchTransactionId mapping, with status tracking (pending, escrowed, settled, failed)
    Webhook handler: Interswitch will POST payment status callbacks — you need an endpoint to receive these and update claim status + trigger WebSocket events

7. Automated Adjudication & Fraud Detection

The PRD describes a rules-based engine comparing submitted ICD-10 codes against the original triage.

Requirements:

    On claim submission, compare submittedICD10 vs triageICD10 — if within allowed deviation parameters, auto-approve
    Fraud flags: time anomalies (claim submitted before triage), location mismatch (patient token used at a different facility than authorized), cost-density outliers (bill amount significantly above historical average for that diagnosis at that hospital)
    Store historical claim metadata per hospital_id + icd10_code for baseline comparison
    Flagged claims go to a manual review queue visible to the HMO claims officer

8. Offline Support (Feature K — Health Passport)

The PRD specifies syncing a compact encrypted JSON to IndexedDB via a "last-known-good" sync.

Requirements (backend side):

    A dedicated /health-passport/sync endpoint that returns a compact, signed JSON payload: { patientId, bloodGroup, allergies, activePlan, lastToken }
    Payload must be small enough to cache meaningfully — target under 10KB
    Sign the payload so the frontend can verify integrity even offline
    Implement a Last-Modified / ETag pattern so the sync only downloads when data has changed

9. Database Schema (High-Level)

Core tables you'll need:

users (id, phone, role, hmo_id, plan_id)
hmos (id, name, policy_matrix_json)
hospitals (id, name, tier, location, wallet_id)
triage_sessions (id, user_id, symptoms, icd10_result, tier_recommendation, token_hash, status)
referral_tokens (id, session_id, encrypted_payload, expires_at, scanned_at)
claims (id, session_id, hospital_id, submitted_icd10, bill_amount, hmo_portion, copay_amount, status)
payments (id, claim_id, interswitch_txn_id, type, status, settled_at)
audit_log (id, actor_id, action, entity_type, entity_id, timestamp)

10. Non-Functional Requirements

Given the PRD's stated goals:

    <3 second triage response → Redis-cached policy matrix, avoid cold DB queries on the hot path
    99.9% uptime → Horizontal scaling behind a load balancer, Redis for session state (not in-memory)
    Low-bandwidth → SSR is a frontend concern, but your APIs should return minimal JSON — no over-fetching, use field projections
    Security → All PII encrypted at rest (AES-256), HTTPS only, audit log every financial action, NDPR compliance for Nigerian data residency

Summary by Phase
Phase	Backend Priority
Phase 1	Auth/OTP, Triage engine, Token generation/scan, WebSocket claims feed
Phase 2	Interswitch escrow + settlement, Co-pay split, Adjudication engine, Fraud flags
Phase 3	Health Passport sync, E-Pharmacy API, Analytics aggregation

Given you're working with Node.js/TypeScript, I'd suggest NestJS for this — the modular architecture maps cleanly to these domains and you already have experience with it. The Interswitch integration and WebSocket layer are your two highest-risk items to de-risk early.

Here's an honest and practical breakdown of the HMO integration landscape for VouchCare:
The Hard Truth First

Nigerian HMOs do not have public APIs the way Stripe or Paystack do. There is no "npm install hmo-nigeria" situation. This is actually a core part of the problem VouchCare is trying to solve — the fragmentation is real and deliberate. You have two realistic paths:
Path 1: Use an Intermediary API Layer (Fastest for MVP)

These companies have already built the HMO integration middleware and expose clean APIs to developers:
🔵 Heala API — Most Developer-Friendly

This is your best bet for the hackathon and MVP.

Heala's API allows you to upload and generate soft-copy IDs for enrollees, validate expiry and benefit access, integrate with pharmaceutical partners for drug delivery, and facilitate test bookings.

Authentication requires an api_token and providerId retrieved from the partner dashboard at partners.heala.io. On your headers you pass Authorization: Api-Key {{api_token}}.

Developer docs: https://developer.heala.io Contact for partner account: tech@heala.ng

What it gives VouchCare:

    Enrollee validation (the core of your QR token flow)
    Benefit access checking (feeds your AI policy triage)
    Pharmacy network integration (Feature J in Phase 3)
    Automated claims submission, validation, adjudication, approvals, and reimbursements — plus digitized referrals, pre-authorizations, and care pathways with real-time decision support.

🟡 WellaHealth — Good for Pharmacy Layer

Their Wella Fulfillment Service (WFS) allows an HMO or Telemedicine team to initiate a dispense process via phone call, email, or API call, providing patient information and prescription details — the engine then sends pickup information to the partner.

Useful for Feature J (E-Pharmacy Handshake) in Phase 3.
🟠 Curacel — Claims Automation

Listed in your own competitor analysis. They have an API focused on automated claims processing and fraud detection. Worth a direct partnership conversation since VouchCare's adjudication engine (Feature G) overlaps with what they do — you might integrate rather than build.
Path 2: Direct HMO Partnership (Longer Term)

For the major HMOs like Hygeia, AXA Mansard, Leadway, and Reliance Health, there are no public APIs. Integration requires a formal B2B partnership. The typical flow is:

    Sign an MOU with the HMO
    Get whitelisted on their provider portal
    Receive sandbox credentials for their internal API (usually a basic REST API or HL7 FHIR endpoint)
    Go through their compliance review

For the buildathon, simulate this. For production, Hygeia and Reliance Health are the two to prioritize given their tech-forward reputation.
What to Actually Build Against (Practical Recommendation)

Given your March 25th deadline, here's what I'd suggest concretely:

For the hackathon demo:

    Sign up at partners.heala.io for a Heala API key
    Use Heala's enrollee validation endpoint to power your QR token verification flow
    Mock the HMO Policy Matrix as a static JSON dataset seeded in Redis — use real Nigerian HMO plan structures (Hygeia, AXA Mansard plan tiers are documented on their websites)
    Use Interswitch for the payment rail (you already have that in the PRD)

    Curacel partnership for claims adjudication rather than building it from scratch

-- ============================================
-- CORE IDENTITY & AUTH
-- ============================================

CREATE TABLE users (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  phone           VARCHAR(15) UNIQUE NOT NULL,
  email           VARCHAR(255) UNIQUE,
  password_hash   VARCHAR(255),
  role            VARCHAR(50) NOT NULL, -- 'patient' | 'receptionist' | 'accountant' | 'medical_director' | 'claims_officer' | 'network_manager' | 'hmo_admin'
  is_active       BOOLEAN DEFAULT TRUE,
  created_at      TIMESTAMPTZ DEFAULT NOW(),
  updated_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE otp_sessions (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  phone           VARCHAR(15) NOT NULL,
  otp_hash        VARCHAR(255) NOT NULL,
  expires_at      TIMESTAMPTZ NOT NULL,
  verified        BOOLEAN DEFAULT FALSE,
  created_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE refresh_tokens (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash      VARCHAR(255) UNIQUE NOT NULL,
  expires_at      TIMESTAMPTZ NOT NULL,
  revoked         BOOLEAN DEFAULT FALSE,
  created_at      TIMESTAMPTZ DEFAULT NOW()
);

-- ============================================
-- HMO & PLAN STRUCTURE
-- ============================================

CREATE TABLE hmos (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name                VARCHAR(255) NOT NULL,
  code                VARCHAR(50) UNIQUE NOT NULL,        -- e.g. 'hygeia', 'axamansard'
  contact_email       VARCHAR(255),
  api_provider        VARCHAR(100),                       -- e.g. 'heala', 'direct', 'curacel'
  api_credentials     JSONB,                              -- encrypted externally before insert
  escrow_wallet_id    VARCHAR(255),                       -- Interswitch wallet ref
  is_active           BOOLEAN DEFAULT TRUE,
  created_at          TIMESTAMPTZ DEFAULT NOW(),
  updated_at          TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE hmo_plans (
  id                      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  hmo_id                  UUID NOT NULL REFERENCES hmos(id),
  name                    VARCHAR(255) NOT NULL,           -- e.g. 'Topaz', 'Diamond'
  code                    VARCHAR(100) NOT NULL,
  covered_tiers           TEXT[] NOT NULL,                 -- ['primary', 'secondary', 'tertiary']
  copay_percentage        NUMERIC(5,2) DEFAULT 0,
  annual_limit            NUMERIC(12,2),
  drug_formulary          TEXT[],                          -- list of covered drug generic names
  covered_icd10_ranges    TEXT[],                          -- e.g. ['A00-B99', 'J00-J99']
  exclusions              JSONB,                           -- specific exclusions
  is_active               BOOLEAN DEFAULT TRUE,
  created_at              TIMESTAMPTZ DEFAULT NOW(),
  updated_at              TIMESTAMPTZ DEFAULT NOW(),

  UNIQUE(hmo_id, code)
);

-- ============================================
-- ENROLLEES (patients linked to an HMO plan)
-- ============================================

CREATE TABLE enrollees (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id             UUID NOT NULL REFERENCES users(id),
  hmo_id              UUID NOT NULL REFERENCES hmos(id),
  plan_id             UUID NOT NULL REFERENCES hmo_plans(id),
  enrollee_number     VARCHAR(100) UNIQUE NOT NULL,        -- HMO-issued ID
  full_name           VARCHAR(255) NOT NULL,
  date_of_birth       DATE,
  gender              VARCHAR(20),
  blood_group         VARCHAR(10),
  genotype            VARCHAR(10),
  allergies           TEXT[],
  policy_start_date   DATE NOT NULL,
  policy_end_date     DATE NOT NULL,
  heala_enrollee_id   VARCHAR(255),                        -- external ref if using Heala API
  is_active           BOOLEAN DEFAULT TRUE,
  created_at          TIMESTAMPTZ DEFAULT NOW(),
  updated_at          TIMESTAMPTZ DEFAULT NOW()
);

-- ============================================
-- HOSPITAL / FACILITY NETWORK
-- ============================================

CREATE TABLE facilities (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name                VARCHAR(255) NOT NULL,
  tier                VARCHAR(20) NOT NULL,                -- 'primary' | 'secondary' | 'tertiary'
  address             TEXT,
  state               VARCHAR(100),
  lga                 VARCHAR(100),
  latitude            NUMERIC(9,6),
  longitude           NUMERIC(9,6),
  phone               VARCHAR(15),
  email               VARCHAR(255),
  wallet_id           VARCHAR(255),                        -- Interswitch settlement wallet
  is_active           BOOLEAN DEFAULT TRUE,
  created_at          TIMESTAMPTZ DEFAULT NOW(),
  updated_at          TIMESTAMPTZ DEFAULT NOW()
);

-- which HMOs a facility is accredited with
CREATE TABLE facility_hmo_accreditations (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  facility_id     UUID NOT NULL REFERENCES facilities(id),
  hmo_id          UUID NOT NULL REFERENCES hmos(id),
  tariff_schedule JSONB,                                   -- agreed pricing per procedure/ICD-10
  accredited_at   DATE,
  is_active       BOOLEAN DEFAULT TRUE,

  UNIQUE(facility_id, hmo_id)
);

-- staff at a facility linked to the users table
CREATE TABLE facility_staff (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID NOT NULL REFERENCES users(id),
  facility_id     UUID NOT NULL REFERENCES facilities(id),
  department      VARCHAR(100),
  is_active       BOOLEAN DEFAULT TRUE,
  created_at      TIMESTAMPTZ DEFAULT NOW(),

  UNIQUE(user_id, facility_id)
);

-- ============================================
-- TRIAGE & REFERRAL ENGINE
-- ============================================

CREATE TABLE triage_sessions (
  id                      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  enrollee_id             UUID NOT NULL REFERENCES enrollees(id),
  raw_symptoms            TEXT NOT NULL,                   -- free-text input from patient
  parsed_symptoms         JSONB,                           -- structured symptom array after NLP
  icd10_codes             TEXT[],                          -- mapped ICD-10 codes
  recommended_tier        VARCHAR(20) NOT NULL,            -- 'primary' | 'secondary' | 'tertiary'
  confidence_score        NUMERIC(4,3),                    -- 0.000 to 1.000
  policy_validated        BOOLEAN DEFAULT FALSE,           -- did plan cover this tier?
  recommended_facility_id UUID REFERENCES facilities(id),
  estimated_copay         NUMERIC(12,2),
  hmo_estimated_portion   NUMERIC(12,2),
  status                  VARCHAR(50) DEFAULT 'pending',   -- 'pending' | 'token_issued' | 'checked_in' | 'completed' | 'expired'
  created_at              TIMESTAMPTZ DEFAULT NOW(),
  updated_at              TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE referral_tokens (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  triage_session_id   UUID NOT NULL REFERENCES triage_sessions(id),
  enrollee_id         UUID NOT NULL REFERENCES enrollees(id),
  facility_id         UUID NOT NULL REFERENCES facilities(id),
  token_hash          VARCHAR(255) UNIQUE NOT NULL,         -- SHA-256 of encrypted payload
  encrypted_payload   TEXT NOT NULL,                        -- AES-256-GCM encrypted blob
  qr_code_url         TEXT,                                 -- stored QR image URL (S3/CDN)
  payment_status      VARCHAR(50) DEFAULT 'guaranteed',     -- 'guaranteed' | 'escrowed' | 'released'
  scanned_at          TIMESTAMPTZ,
  scanned_by_user_id  UUID REFERENCES users(id),
  expires_at          TIMESTAMPTZ NOT NULL,                  -- rolling 60s TTL, refreshed on activity
  is_used             BOOLEAN DEFAULT FALSE,
  created_at          TIMESTAMPTZ DEFAULT NOW()
);

-- ============================================
-- CLAIMS LIFECYCLE
-- ============================================

CREATE TABLE claims (
  id                      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  referral_token_id       UUID NOT NULL REFERENCES referral_tokens(id),
  triage_session_id       UUID NOT NULL REFERENCES triage_sessions(id),
  enrollee_id             UUID NOT NULL REFERENCES enrollees(id),
  facility_id             UUID NOT NULL REFERENCES facilities(id),
  hmo_id                  UUID NOT NULL REFERENCES hmos(id),
  submitted_icd10_codes   TEXT[],                          -- what hospital actually submitted
  procedures              JSONB,                           -- procedure codes + descriptions
  gross_bill_amount       NUMERIC(12,2) NOT NULL,
  hmo_allowable_amount    NUMERIC(12,2),                   -- from tariff schedule
  copay_amount            NUMERIC(12,2),
  discount_amount         NUMERIC(12,2) DEFAULT 0,
  net_bill_amount         NUMERIC(12,2),
  adjudication_status     VARCHAR(50) DEFAULT 'pending',   -- 'pending' | 'auto_approved' | 'manual_review' | 'approved' | 'rejected' | 'flagged'
  adjudicated_at          TIMESTAMPTZ,
  adjudicated_by_user_id  UUID REFERENCES users(id),       -- NULL if auto-adjudicated
  rejection_reason        TEXT,
  fraud_flag              BOOLEAN DEFAULT FALSE,
  fraud_reason            TEXT,
  created_at              TIMESTAMPTZ DEFAULT NOW(),
  updated_at              TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE claim_line_items (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  claim_id        UUID NOT NULL REFERENCES claims(id) ON DELETE CASCADE,
  description     VARCHAR(255) NOT NULL,
  icd10_code      VARCHAR(20),
  quantity        INTEGER DEFAULT 1,
  unit_price      NUMERIC(12,2) NOT NULL,
  total_price     NUMERIC(12,2) NOT NULL,
  covered         BOOLEAN DEFAULT TRUE,
  created_at      TIMESTAMPTZ DEFAULT NOW()
);

-- ============================================
-- PAYMENTS & SETTLEMENT
-- ============================================

CREATE TABLE payments (
  id                          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  claim_id                    UUID NOT NULL REFERENCES claims(id),
  payment_type                VARCHAR(50) NOT NULL,         -- 'hmo_settlement' | 'copay' | 'escrow_hold' | 'escrow_release'
  payer_type                  VARCHAR(50) NOT NULL,         -- 'hmo' | 'patient' | 'escrow'
  payee_type                  VARCHAR(50) NOT NULL,         -- 'hospital' | 'escrow'
  amount                      NUMERIC(12,2) NOT NULL,
  currency                    VARCHAR(10) DEFAULT 'NGN',
  interswitch_reference       VARCHAR(255) UNIQUE,          -- Interswitch txn ref
  interswitch_transaction_id  VARCHAR(255),
  payment_method              VARCHAR(50),                  -- 'transfer' | 'webpay' | 'paycode'
  paycode                     VARCHAR(50),                  -- for cardless Interswitch paycode
  status                      VARCHAR(50) DEFAULT 'initiated', -- 'initiated' | 'pending' | 'successful' | 'failed' | 'reversed'
  initiated_at                TIMESTAMPTZ DEFAULT NOW(),
  settled_at                  TIMESTAMPTZ,
  webhook_payload             JSONB,                        -- raw Interswitch webhook body
  created_at                  TIMESTAMPTZ DEFAULT NOW(),
  updated_at                  TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE escrow_ledger (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  hmo_id          UUID NOT NULL REFERENCES hmos(id),
  claim_id        UUID REFERENCES claims(id),
  entry_type      VARCHAR(50) NOT NULL,                     -- 'hold' | 'release' | 'refund' | 'top_up'
  amount          NUMERIC(12,2) NOT NULL,
  balance_after   NUMERIC(12,2) NOT NULL,
  reference       VARCHAR(255),
  created_at      TIMESTAMPTZ DEFAULT NOW()
);

-- ============================================
-- FRAUD DETECTION
-- ============================================

CREATE TABLE fraud_signals (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  claim_id        UUID NOT NULL REFERENCES claims(id),
  signal_type     VARCHAR(100) NOT NULL,                    -- 'icd10_mismatch' | 'cost_outlier' | 'location_mismatch' | 'time_anomaly' | 'duplicate_claim'
  severity        VARCHAR(20) NOT NULL,                     -- 'low' | 'medium' | 'high'
  description     TEXT,
  resolved        BOOLEAN DEFAULT FALSE,
  resolved_by     UUID REFERENCES users(id),
  resolved_at     TIMESTAMPTZ,
  created_at      TIMESTAMPTZ DEFAULT NOW()
);

-- historical baseline for fraud detection comparisons

  avg_cost        NUMERIC(12,2) NOT NULL,
  std_deviation   NUMERIC(12,2),
  sample_size     INTEGER,
  computed_at     TIMESTAMPTZ DEFAULT NOW(),

  UNIQUE(facility_id, icd10_code)

  payload_hash    VARCHAR(255) NOT NULL,                    -- hash of current payload for ETag
  signed_payload  TEXT NOT NULL,                            -- compact signed JSON for IndexedDB sync
  last_synced_at  TIMESTAMPTZ DEFAULT NOW(),
  updated_at      TIMESTAMPTZ DEFAULT NOW()

3. HMO Policy Validation

This is what makes VouchCare different from just a symptom checker. After ICD-10 codes are returned, you must cross-reference against the enrollee's specific plan.

Validation logic:
typescript

function validateAgainstPolicy(
  icd10Codes: string[],
  recommendedTier: string,
  policy: PolicyMatrix,
  enrolleeAnnualSpend: number
): PolicyValidationResult {

  // 1. Check if recommended tier is covered
  const tierCovered = policy.covered_tiers.includes(recommendedTier)

  // 2. Check if any ICD-10 code falls in covered ranges
  const icd10Covered = icd10Codes.some(code =>
    isInCoveredRange(code, policy.covered_icd10_ranges) &&
    !policy.excluded_icd10_codes.includes(code)
  )

  // 3. Check annual limit not exceeded
  const withinLimit = enrolleeAnnualSpend < policy.annual_limit

  // 4. Calculate co-pay
  const estimatedBill = getEstimatedBill(icd10Codes, recommendedTier)
  const copay = estimatedBill * (policy.copay_percentage / 100)
  const hmoPortion = estimatedBill - copay

  return {
    approved: tierCovered && icd10Covered && withinLimit,
    denial_reason: !tierCovered ? 'tier_not_covered'
                 : !icd10Covered ? 'condition_excluded'
                 : 'annual_limit_exceeded',
    copay,
    hmo_portion: hmoPortion,
    pre_auth_required: policy.pre_auth_required_tiers.includes(recommendedTier)
  }
}

4. Facility Matching

After tier and policy validation, find the right hospital.

Requirements:

    Filter facilities by tier = recommendedTier
    Filter by facility_hmo_accreditations where hmo_id = enrollee.hmo_id and is_active = true
    Sort by proximity using PostGIS or a simple Haversine distance calculation against the patient's coordinates

    If no facility found within 10km, expand radius to 25km, then 50km — never return an empty list without explanation

Haversine query (no PostGIS needed for MVP):
sql

SELECT
  f.id,
  f.name,
  f.tier,
  f.address,
  f.phone,
  (
    6371 * acos(
      cos(radians($1)) * cos(radians(f.latitude)) *
      cos(radians(f.longitude) - radians($2)) +
      sin(radians($1)) * sin(radians(f.latitude))
    )
  ) AS distance_km
FROM facilities f
INNER JOIN facility_hmo_accreditations fha
  ON fha.facility_id = f.id
  AND fha.hmo_id = $3
  AND fha.is_active = true
WHERE f.tier = $4
  AND f.is_active = true
ORDER BY distance_km ASC
LIMIT 3;

const EMERGENCY_KEYWORD_PATTERNS = [
  /chest\s*pain/i,
  /can.{0,5}t\s*breath/i,
  /difficulty\s*breath/i,
  /stroke/i,
  /unconsci/i,
  /not\s*respond/i,

@Injectable()
export class TriageService {
  private readonly logger = new Logger(TriageService.name)
  private readonly anthropic: Anthropic

  constructor(
    @InjectRepository(TriageSession)
    private triageRepo: Repository<TriageSession>,
    @InjectRedis() private redis: Redis,
    private policyMatrix: PolicyMatrixService,
    private facilityMatch: FacilityMatchService,
    private rulesEngine: RulesEngineService,
  ) {
    this.anthropic = new Anthropic({
      apiKey: process.env.ANTHROPIC_API_KEY,

  // ─────────────────────────────────────────────
  // MAIN ENTRY POINT
  // ─────────────────────────────────────────────
  async runTriage(
    enrollee: Enrollee,
    input: TriageInput,
  ): Promise<TriageResult> {
    // 1. Emergency keyword check — runs synchronously, no LLM needed
    const isEmergency = this.detectEmergencyKeywords(input.symptoms)
    if (isEmergency) {
      return this.buildEmergencyResponse(enrollee, input)
    }

    // 2. Run LLM parsing + policy matrix fetch in PARALLEL
    // This is how we stay under 3 seconds — never await sequentially
    const [llmResult, policyMatrix] = await Promise.all([
      this.callLLMWithFallback(input.symptoms, enrollee),
      this.policyMatrix.getForEnrollee(enrollee.hmoId, enrollee.planId),
    ])

    // 3. Second emergency check — on ICD-10 codes returned by LLM
    const hasEmergencyCode = llmResult.icd10Codes.some(code =>
      EMERGENCY_ICD10_PREFIXES.some(prefix => code.startsWith(prefix)),
    )
    if (hasEmergencyCode) {
      return this.buildEmergencyResponse(enrollee, input)
    }

    // 4. Policy validation
    const policyResult = this.policyMatrix.validate(
      llmResult.icd10Codes,
      llmResult.recommendedTier,
      policyMatrix,
      enrollee.annualSpendToDate,
    )

    // 5. Facility matching (runs after tier is confirmed)
    const facilities = await this.facilityMatch.findNearest({
      tier: llmResult.recommendedTier,
      hmoId: enrollee.hmoId,
      latitude: input.latitude,
      longitude: input.longitude,
    })

    // 6. Persist triage session
    const session = await this.triageRepo.save({
      enrolleeId: enrollee.id,
      rawSymptoms: input.symptoms,
      parsedSymptoms: llmResult.parsedSymptoms,
      icd10Codes: llmResult.icd10Codes,
      recommendedTier: llmResult.recommendedTier,
      confidenceScore: llmResult.confidenceScore,
      urgencyLevel: llmResult.urgencyLevel,
      reasoning: llmResult.reasoning,
      policyValidated: policyResult.approved,
      estimatedCopay: policyResult.copay,
      hmoEstimatedPortion: policyResult.hmoPortion,
      recommendedFacilityId: facilities[0]?.id ?? null,
      status: 'pending',
    })

    return {
      sessionId: session.id,
      urgencyLevel: llmResult.urgencyLevel,
      recommendedTier: llmResult.recommendedTier,
      icd10Codes: llmResult.icd10Codes,
      confidenceScore: llmResult.confidenceScore,
      reasoning: llmResult.reasoning,
      policyResult,
      facilities,
      disclaimer:
        'This is a triage guide only. It is not a medical diagnosis. ' +
        'Always follow the advice of a qualified healthcare professional.',
      lowConfidenceWarning:
        llmResult.confidenceScore < 0.6
          ? 'Our confidence in this assessment is low. ' +
            'We recommend describing your symptoms in more detail ' +
            'or consulting a doctor directly.'
          : null,
    }
  }

  // ─────────────────────────────────────────────
  // LLM CALL WITH FALLBACK
  // Times out at 1500ms → falls back to rules engine
  // ─────────────────────────────────────────────
  private async callLLMWithFallback(
    symptoms: string,
    enrollee: Enrollee,
  ): Promise<LLMTriageOutput> {
    try {
      const result = await Promise.race([
        this.callClaude(symptoms, enrollee),
        this.timeout(1500),
      ])
      return result as LLMTriageOutput
    } catch (err) {
      this.logger.warn(
        `LLM triage timed out or failed, falling back to rules engine: ${err.message}`,
      )
      return this.rulesEngine.analyze(symptoms)
    }
  }

  // ─────────────────────────────────────────────
  // CLAUDE API CALL
  // ─────────────────────────────────────────────
  private async callClaude(
    symptoms: string,
    enrollee: Enrollee,
  ): Promise<LLMTriageOutput> {
    const response = await this.anthropic.messages.create({
      model: 'claude-haiku-4-5',
      max_tokens: 512, // Keep output tight — we only need structured JSON
      system: this.buildSystemPrompt(),
      messages: [
        {
          role: 'user',
          content: this.buildUserPrompt(symptoms, enrollee),
        },
      ],
    })

    const raw = response.content[0].type === 'text'
      ? response.content[0].text
      : ''

    return this.parseAndValidateLLMResponse(raw)
  }

  // ─────────────────────────────────────────────
  // SYSTEM PROMPT
  // This is the core prompt engineering
  // ─────────────────────────────────────────────
  private buildSystemPrompt(): string {
    return `

  // ─────────────────────────────────────────────
  // USER PROMPT
  // Inject patient context to reduce hallucination
  // ─────────────────────────────────────────────
  private buildUserPrompt(symptoms: string, enrollee: Enrollee): string {
    // Sanitize input — strip any HTML or injection attempts
    const sanitized = symptoms
      .replace(/<[^>]*>/g, '')
      .replace(/[{}[\]]/g, '')
      .trim()
      .slice(0, 1000) // Hard cap

    // Including age, gender, and known conditions improves ICD-10 accuracy significantly
    const patientContext = [
      enrollee.dateOfBirth
        ? `Age: ${this.calculateAge(enrollee.dateOfBirth)}`
        : null,
      enrollee.gender ? `Gender: ${enrollee.gender}` : null,
      enrollee.allergies?.length
        ? `Known allergies: ${enrollee.allergies.join(', ')}`
        : null,
      enrollee.bloodGroup
        ? `Blood group: ${enrollee.bloodGroup}`
        : null,
    ]
      .filter(Boolean)
      .join(' | ')

    return `
Patient context: ${patientContext || 'Not provided'}

Patient symptom description:
"${sanitized}"

Analyze these symptoms and return the JSON triage assessment.
`.trim()
  }

  // ─────────────────────────────────────────────
  // RESPONSE PARSING & VALIDATION
  // Never trust raw LLM output — always validate
  // ─────────────────────────────────────────────
  private parseAndValidateLLMResponse(raw: string): LLMTriageOutput {
    let parsed: any

    try {
      // Strip any accidental markdown fences the model might add
      const cleaned = raw
        .replace(/```json/gi, '')
        .replace(/```/g, '')
        .trim()
      parsed = JSON.parse(cleaned)
    } catch {
      throw new Error(`LLM returned invalid JSON: ${raw.slice(0, 100)}`)
    }

    // Schema validation — every field must be present and valid type
    const validTiers = ['primary', 'secondary', 'tertiary']
    const validUrgency = ['non_urgent', 'urgent', 'emergency']

    if (!validTiers.includes(parsed.recommended_tier)) {
      throw new Error(`Invalid tier: ${parsed.recommended_tier}`)
    }
    if (!validUrgency.includes(parsed.urgency_level)) {
      throw new Error(`Invalid urgency: ${parsed.urgency_level}`)
    }
    if (
      typeof parsed.confidence_score !== 'number' ||
      parsed.confidence_score < 0 ||
      parsed.confidence_score > 1
    ) {
      throw new Error(`Invalid confidence_score: ${parsed.confidence_score}`)
    }
    if (!Array.isArray(parsed.icd10_codes) || parsed.icd10_codes.length === 0) {
      throw new Error('icd10_codes must be a non-empty array')
    }

    // Validate ICD-10 format — basic regex check (X00.0 pattern)
    const icd10Regex = /^[A-Z]\d{2}(\.\d{1,4})?$/
    const validCodes = parsed.icd10_codes.filter((code: string) =>
      icd10Regex.test(code),
    )
    if (validCodes.length === 0) {
      throw new Error('No valid ICD-10 codes returned')
    }

    return {
      parsedSymptoms: Array.isArray(parsed.parsed_symptoms)
        ? parsed.parsed_symptoms
        : [],
      icd10Codes: validCodes,
      urgencyLevel: parsed.urgency_level as UrgencyLevel,
      recommendedTier: parsed.recommended_tier,
      confidenceScore: parsed.confidence_score,
      reasoning: typeof parsed.reasoning === 'string'
        ? parsed.reasoning.slice(0, 500) // Cap reasoning length
        : 'Assessment based on reported symptoms.',
    }
  }

  // ─────────────────────────────────────────────
  // EMERGENCY RESPONSE BUILDER
  // Bypasses normal triage flow entirely
  // ─────────────────────────────────────────────
  private async buildEmergencyResponse(
    enrollee: Enrollee,
    input: TriageInput,
  ): Promise<TriageResult> {
    const nearestTertiary = await this.facilityMatch.findNearest({
      tier: 'tertiary',
      hmoId: enrollee.hmoId,
      latitude: input.latitude,
      longitude: input.longitude,
    })

    return {
      sessionId: null,
      urgencyLevel: 'emergency',
      recommendedTier: 'tertiary',
      icd10Codes: [],
      confidenceScore: 1.0,
      reasoning: 'Emergency symptoms detected. Immediate medical attention required.',
      policyResult: null,
      facilities: nearestTertiary,
      isEmergency: true,
      emergencyMessage:
        '🚨 Your symptoms may indicate a medical emergency. ' +
        'Please go to the nearest emergency room immediately or call 112.',
      disclaimer: null,
      lowConfidenceWarning: null,
    }
  }

  // ─────────────────────────────────────────────
  // HELPERS
  // ─────────────────────────────────────────────
  private detectEmergencyKeywords(symptoms: string): boolean {
    return EMERGENCY_KEYWORD_PATTERNS.some(pattern => pattern.test(symptoms))
  }

  private timeout(ms: number): Promise<never> {
    return new Promise((_, reject) =>
      setTimeout(() => reject(new Error('LLM timeout')), ms),
    )
  }

  private calculateAge(dob: Date): number {
    const today = new Date()
    const birthDate = new Date(dob)
    let age = today.getFullYear() - birthDate.getFullYear()
    const monthDiff = today.getMonth() - birthDate.getMonth()
    if (monthDiff < 0 || (monthDiff === 0 && today.getDate() < birthDate.getDate())) {
      age--
    }
    return age
  }

    let bestMatchCount = 0

    for (const rule of SYMPTOM_RULES) {

        reasoning:
          'Symptoms unclear from description. Recommending primary care for evaluation.',
      }
    }

    return {
      parsedSymptoms: [symptoms],
      icd10Codes: bestMatch.icd10Codes,
      urgencyLevel: bestMatch.urgency,
      recommendedTier: bestMatch.tier,
      confidenceScore: bestMatch.confidence * (bestMatchCount / bestMatch.keywords.length),
      reasoning: `Rules-based assessment. Symptom pattern matches ${bestMatch.icd10Codes[0]} category.`,

import { PolicyMatrix, PolicyValidationResult } from './types'

@Injectable()
export class PolicyMatrixService {
  constructor(
    @InjectRedis() private redis: Redis,
    @InjectRepository(HmoPlan)
    private planRepo: Repository<HmoPlan>,
  ) {}

  async getForEnrollee(hmoId: string, planId: string): Promise<PolicyMatrix> {
    const cacheKey = `policy_matrix:${hmoId}:${planId}`

    // Try Redis first — O(1) lookup
    const cached = await this.redis.get(cacheKey)
    if (cached) return JSON.parse(cached)

    // Cache miss — fetch from DB and warm the cache
    const plan = await this.planRepo.findOne({
      where: { id: planId, hmoId },
    })

    if (!plan) throw new Error(`Plan not found: ${planId}`)

    const matrix: PolicyMatrix = {
      hmoId,
      planId,
      coveredTiers: plan.coveredTiers,
      coveredIcd10Ranges: plan.coveredIcd10Ranges,
      excludedIcd10Codes: plan.exclusions?.excludedCodes ?? [],
      copayPercentage: plan.copayPercentage,
      annualLimit: plan.annualLimit,
      drugFormulary: plan.drugFormulary,
      preAuthRequiredTiers: plan.exclusions?.preAuthTiers ?? [],
    }

    // Cache for 24 hours
    await this.redis.setex(cacheKey, 86400, JSON.stringify(matrix))

    return matrix
  }

  validate(
    icd10Codes: string[],
    recommendedTier: string,
    policy: PolicyMatrix,
    annualSpendToDate: number,
  ): PolicyValidationResult {
    const tierCovered = policy.coveredTiers.includes(recommendedTier)

    const icd10Covered = icd10Codes.some(code =>
      this.isInCoveredRange(code, policy.coveredIcd10Ranges) &&
      !policy.excludedIcd10Codes.includes(code),
    )

    const withinLimit =
      !policy.annualLimit || annualSpendToDate < policy.annualLimit

    // Estimate bill using a flat-rate lookup (expand this with tariff data)
    const estimatedBill = this.estimateBill(recommendedTier)
    const copay = estimatedBill * (policy.copayPercentage / 100)
    const hmoPortion = estimatedBill - copay

    const approved = tierCovered && icd10Covered && withinLimit

    return {
      approved,
      denialReason: !tierCovered
        ? 'tier_not_covered'
        : !icd10Covered
          ? 'condition_excluded'
          : !withinLimit
            ? 'annual_limit_exceeded'
            : null,
      copay,
      hmoPortion,
      estimatedBill,
      preAuthRequired: policy.preAuthRequiredTiers.includes(recommendedTier),
    }
  }

  private isInCoveredRange(code: string, ranges: string[]): boolean {
    return ranges.some(range => {
      const [start, end] = range.split('-')
      if (!end) return code.startsWith(start)
      // Compare letter prefix + numeric range
      const codePrefix = code.charAt(0)
      const startPrefix = start.charAt(0)
      const endPrefix = end.charAt(0)
      if (codePrefix < startPrefix || codePrefix > endPrefix) return false
      const codeNum = parseFloat(code.slice(1))
      const startNum = parseFloat(start.slice(1))
      const endNum = parseFloat(end.slice(1))
      return codeNum >= startNum && codeNum <= endNum
    })
  }

  private estimateBill(tier: string): number {
    // Flat estimates in NGN — replace with tariff schedule per facility later
    const estimates: Record<string, number> = {
      primary: 5000,
      secondary: 25000,
      tertiary: 80000,
    }
    return estimates[tier] ?? 5000
  }
}

Prompt Engineering — Key Decisions Explained

A few things in the prompts that matter a lot:

Why max_tokens: 512 — Haiku is fast but you're paying per output token. The JSON response you need is ~150 tokens. Setting 512 gives breathing room without letting the model ramble.

Why patient context in the user prompt, not the system prompt — System prompt is cached by Anthropic (reducing cost on repeated calls). Patient context changes per request so it goes in the user turn.

The Pidgin examples in the system prompt — "body dey hot", "e dey purge" — these are real phrases Nigerian patients will type. Without these, the model treats them as unknown input and confidence drops. This single addition meaningfully improves accuracy for the Musa persona.

Why reasoning is capped at 500 chars — It goes into the audit_log. You don't want unbounded strings in your DB from LLM output.

The double emergency check — keyword check runs before the LLM (free, synchronous), ICD-10 check runs after (catches cases the keyword check misses like a patient who types clinical terms). Belt and suspenders.

Why throw on validation failure — The parseAndValidateLLMResponse throws rather than returning a default. This forces the callLLMWithFallback catch block to route to the rules engine, giving you a clean separation: LLM output is either valid or falls back. Never accept partial/malformed LLM output silently in healthcare.

import Groq from 'groq-sdk'
import { GoogleGenerativeAI } from '@google/generative-ai'
import { Injectable, Logger } from '@nestjs/common'
import { LLMTriageOutput } from './types'

@Injectable()
export class LLMService {
  private readonly logger = new Logger(LLMService.name)

  // Primary: Groq (free, fast)
  private readonly groq = new Groq({
    apiKey: process.env.GROQ_API_KEY,
  })

  // Fallback: Gemini 2.5 Flash-Lite (free, different provider)
  private readonly gemini = new GoogleGenerativeAI(
    process.env.GEMINI_API_KEY,
  )

  async callWithFallback(
    systemPrompt: string,
    userPrompt: string,
  ): Promise<LLMTriageOutput> {
    // Try Groq first — fastest and most generous free tier
    try {
      return await Promise.race([
        this.callGroq(systemPrompt, userPrompt),
        this.timeout(1500),
      ]) as LLMTriageOutput
    } catch (groqError) {
      this.logger.warn(`Groq failed: ${groqError.message}. Trying Gemini...`)
    }

    // Fallback to Gemini if Groq rate limits or fails
    try {
      return await Promise.race([
        this.callGemini(systemPrompt, userPrompt),
        this.timeout(2000),
      ]) as LLMTriageOutput
    } catch (geminiError) {
      this.logger.warn(`Gemini failed: ${geminiError.message}. Using rules engine.`)
      // Signal to TriageService to use rules engine
      throw new Error('ALL_LLM_PROVIDERS_FAILED')
    }
  }

  // ─────────────────────────────────────────
  // GROQ — Primary (Free, Fast)
  // Model: llama-3.3-70b-versatile for quality
  // Swap to llama-3.1-8b-instant if hitting rate limits
  // ─────────────────────────────────────────
  private async callGroq(
    systemPrompt: string,
    userPrompt: string,
  ): Promise<LLMTriageOutput> {
    const response = await this.groq.chat.completions.create({
      model: 'llama-3.3-70b-versatile',
      max_tokens: 512,
      temperature: 0,       // Zero temp = deterministic JSON, no creativity needed
      messages: [
        { role: 'system', content: systemPrompt },
        { role: 'user', content: userPrompt },
      ],
    })

    const raw = response.choices[0]?.message?.content ?? ''
    return this.parseResponse(raw)
  }

  // ─────────────────────────────────────────
  // GEMINI — Fallback (Free, Higher quality)
  // Model: gemini-2.5-flash-lite (1000 RPD free)
  // ─────────────────────────────────────────
  private async callGemini(
    systemPrompt: string,
    userPrompt: string,
  ): Promise<LLMTriageOutput> {
    const model = this.gemini.getGenerativeModel({
      model: 'gemini-2.5-flash-lite',
      generationConfig: {
        maxOutputTokens: 512,
        temperature: 0,
        responseMimeType: 'application/json', // Forces JSON output natively
      },
      systemInstruction: systemPrompt,
    })

    const result = await model.generateContent(userPrompt)
    const raw = result.response.text()
    return this.parseResponse(raw)
  }

  // ─────────────────────────────────────────
  // SHARED RESPONSE PARSER
  // ─────────────────────────────────────────
  private parseResponse(raw: string): LLMTriageOutput {
    const cleaned = raw
      .replace(/```json/gi, '')
      .replace(/```/g, '')
      .trim()

    let parsed: any
    try {
      parsed = JSON.parse(cleaned)
    } catch {
      throw new Error(`Invalid JSON from LLM: ${raw.slice(0, 100)}`)
    }

    // Validate required fields
    const validTiers = ['primary', 'secondary', 'tertiary']
    const validUrgency = ['non_urgent', 'urgent', 'emergency']

    if (!validTiers.includes(parsed.recommended_tier))
      throw new Error(`Bad tier: ${parsed.recommended_tier}`)
    if (!validUrgency.includes(parsed.urgency_level))
      throw new Error(`Bad urgency: ${parsed.urgency_level}`)
    if (typeof parsed.confidence_score !== 'number')
      throw new Error('Missing confidence_score')

    const icd10Regex = /^[A-Z]\d{2}(\.\d{1,4})?$/
    const validCodes = (parsed.icd10_codes ?? []).filter((c: string) =>
      icd10Regex.test(c),
    )
    if (validCodes.length === 0)
      throw new Error('No valid ICD-10 codes')

    return {
      parsedSymptoms: parsed.parsed_symptoms ?? [],
      icd10Codes: validCodes,
      urgencyLevel: parsed.urgency_level,
      recommendedTier: parsed.recommended_tier,
      confidenceScore: Math.min(1, Math.max(0, parsed.confidence_score)),
      reasoning: (parsed.reasoning ?? '').slice(0, 500),
    }
  }

  private timeout(ms: number): Promise<never> {
    return new Promise((_, reject) =>
      setTimeout(() => reject(new Error(`Timeout after ${ms}ms`)), ms),
    )
  }
}

  constructor(private rulesEngine: RulesEngineService) {}

    const model = this.gemini.getGenerativeModel({

        maxOutputTokens: 512,

        responseMimeType: 'application/json',

      this.buildUserPrompt(symptoms),
    )

    const raw = result.response.text()
    return this.parse(raw)
  }

  private buildSystemPrompt(): string {
    return `
      You are a clinical triage assistant for VouchCare, a Nigerian healthcare platform.
      Return ONLY valid JSON. No explanations, no markdown.
      
      JSON shape:
      {
        "parsed_symptoms": string[],
        "icd10_codes": string[],
        "urgency_level": "non_urgent" | "urgent" | "emergency",
        "recommended_tier": "primary" | "secondary" | "tertiary",
        "confidence_score": number,
        "reasoning": string
      }
      
      Nigerian context: "body dey hot" = fever, "e dey purge" = diarrhea,
      "my head dey bang" = severe headache, "e wan born" = in labour.
      
      Tier guide:
      - primary: malaria, cold, minor infections, routine checkups
      - secondary: fractures, moderate infections, maternity, minor surgery  
      - tertiary: cardiac, stroke, severe trauma, complex surgery
    `.trim()
  }

  private buildUserPrompt(symptoms: string): string {
    // Sanitize — strip HTML and script injections
    const clean = symptoms
      .replace(/<[^>]*>/g, '')
      .trim()
      .slice(0, 1000)

    return `Patient symptoms: "${clean}"\n\nReturn the JSON triage assessment.`
  }

  private parse(raw: string): LLMTriageOutput {
    let parsed: any

    try {
      // Gemini with responseMimeType: 'application/json' 
      // usually returns clean JSON — but strip fences just in case
      const clean = raw.replace(/```json|```/gi, '').trim()
      parsed = JSON.parse(clean)
    } catch {
      throw new Error(`Gemini returned invalid JSON: ${raw.slice(0, 100)}`)
    }

    // Validate shape
    const validTiers = ['primary', 'secondary', 'tertiary']
    const validUrgency = ['non_urgent', 'urgent', 'emergency']

    if (!validTiers.includes(parsed.recommended_tier))
      throw new Error(`Invalid tier: ${parsed.recommended_tier}`)
    if (!validUrgency.includes(parsed.urgency_level))
      throw new Error(`Invalid urgency: ${parsed.urgency_level}`)

    return {
      parsedSymptoms: parsed.parsed_symptoms ?? [],
      icd10Codes: parsed.icd10_codes ?? [],
      urgencyLevel: parsed.urgency_level,
      recommendedTier: parsed.recommended_tier,
      confidenceScore: parsed.confidence_score ?? 0.5,
      reasoning: (parsed.reasoning ?? '').slice(0, 500),
    }
  }

  private timeout(ms: number): Promise<never> {
    return new Promise((_, reject) =>
      setTimeout(() => reject(new Error(`Timeout ${ms}ms`)), ms),
    )
  }
}

### ❌ The Real Problem — WebSockets

**This is the main blocker.** Your real-time claims dashboard requires WebSockets — a persistent connection that pushes `claim:new`, `claim:authorized`, `claim:settled` events to hospital staff in real time.

TanStack Start currently has **no built-in WebSocket support**. Server functions are request/response — they can't hold open a connection.

Your options:

**Option A — Separate WebSocket server (recommended)**
Run a small standalone Node.js + Socket.io server alongside your TanStack Start app. TanStack Start handles all the REST/server function logic, the WS server handles real-time events. They share the same Redis pub/sub channel.
```
TanStack Start app  →  server functions (REST)
                    ↘
Redis pub/sub  →  WS server (Socket.io)  →  browser

Option B — Polling (simpler, good enough for MVP) Replace WebSockets with polling on a 3–5 second interval from the hospital dashboard. Not as slick but entirely achievable with server functions:

Option C — Server-Sent Events (SSE) One-way push from server to client. Easier than WebSockets, works for the claims dashboard since it's read-only from the client's perspective. Vinxi supports SSE via event streams.

// app/server/auth.ts
import { createServerFn } from '@tanstack/start'
import { resend } from './lib/email'
import { redis } from './lib/redis'
import { db } from './lib/db'
import * as bcrypt from 'bcrypt'

export const sendOtp = createServerFn({ method: 'POST' })
  .validator((data: { email: string }) => data)
  .handler(async ({ data }) => {
    // Generate 6-digit OTP
    const otp = Math.floor(100000 + Math.random() * 900000).toString()
    const otpHash = await bcrypt.hash(otp, 10)

    // Store in Redis with 10-minute TTL
    await redis.setex(`otp:${data.email}`, 600, otpHash)

    // Send via Resend
    await resend.emails.send({
      from: 'VouchCare <auth@yourdomain.com>',
      to: data.email,
      subject: 'Your VouchCare verification code',
      html: `
        <div style="font-family: Arial, sans-serif; max-width: 400px; margin: 0 auto;">
          <h2 style="color: #1B4F8A;">VouchCare</h2>
          <p>Your verification code is:</p>
          <h1 style="letter-spacing: 8px; color: #1B4F8A; font-size: 36px;">${otp}</h1>
          <p style="color: #555;">This code expires in 10 minutes.</p>
          <p style="color: #555; font-size: 12px;">
            If you did not request this, please ignore this email.
          </p>
        </div>
      `
    })

    return { sent: true }
  })

export const verifyOtp = createServerFn({ method: 'POST' })
  .validator((data: { email: string; otp: string }) => data)
  .handler(async ({ data }) => {
    const stored = await redis.get(`otp:${data.email}`)
    if (!stored) throw new Error('OTP expired or not found')

    const valid = await bcrypt.compare(data.otp, stored)
    if (!valid) throw new Error('Invalid OTP')

    // Delete OTP so it cannot be reused
    await redis.del(`otp:${data.email}`)

    // Upsert user
    const user = await db.user.upsert({
      where: { email: data.email },
      update: {},
      create: { email: data.email, role: 'PATIENT' },
    })

    return { userId: user.id }
  })
